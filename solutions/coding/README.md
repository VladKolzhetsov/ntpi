# coding — версионирование солверов

Задача типа: в `workspace/` лежит модуль с багами (`mylib.py`) и
корректные тесты (`test_mylib.py`, «do not edit the tests»). Инструкция:
«Run `python3 test_mylib.py` … Fix the bugs in mylib.py … write ONLY the
word DONE to answer.txt». Проверка скрытая: `check=unittest`,
`expected=tests_pass` — балл, по-видимому, даётся за зелёный прогон
тестов в workspace. Баги в тренировке — однотокеновые мутации
(`s -= x` вместо `+=`, `x < best` вместо `>`, `sorted` вместо `reversed`,
`% 2 == 1` вместо `== 0`).

Артефакт решения — ДВА файла: исправленный `mylib.py` (перезаписываем
в workspace) и `answer.txt` = `DONE` в обе позиции. Только `answer.txt`
без фикса балла не даёт.

## v1 «в лоб» (`v1/solver.py`)

Один вызов LLM, без итераций и фидбэка тестов — чистый замер «чинит ли
модель баги по исходникам и ассертам за раз»:

```
precheck (0 токенов) → промпт: инструкция + все .py workspace
→ полный исправленный модуль в ответе → ast.parse → запись mylib.py
→ python3 test_mylib.py (сабпроцесс, cwd=workspace) → exit 0 → DONE
```

Детерминированные шаги (precheck-гейт, 0 токенов → unanswerable):
- нет .py-файлов в workspace;
- файл, названный в «Fix the bugs in X.py», отсутствует;
- инструкция велит чинить тест-файл (противоречит «do not edit»);
- нет тестовой команды/файла: команда парсится из бэктиков инструкции
  с whitelist'ом (`python3 X.py`, без путей и `..`) и проверкой
  существования файла; fallback — единственный `test_*.py`.

Гарантии целостности:
- ответ валидируется `ast.parse` ДО записи: мусор не портит workspace;
- тесты не перезаписываем никогда (записываем только target-модуль);
- команда тестов — только из whitelist'а (бэктики `rm -rf /` игнорируются).

Демо работает на КОПИИ задачи в tmpdir: солвер перезаписывает `mylib.py`,
а тренировочный набор должен оставаться воспроизводимым.

Живой прогон (noreason, temp 0, на копиях): **2/2**:

| Задача | Багов | Результат | Стоимость |
|---|---|---|---|
| coding_0003 | 2 (`sorted`/`-=`) | ✓ DONE, тесты OK | 631.4 экв. |
| coding_0007 | 2 (`<`/`%2==1`) | ✓ DONE, тесты OK | 298.1 экв. |

Стоимость выше math/DA (~50–220 экв.): в ответе — полный текст модуля,
а модель иногда добавляет пояснения до кода. Разброс 298–631 при
одинаковой структуре — длина ответа прокси при temp 0.

Уроки v1:
- однотокеновые мутации чинятся одним вызовом без фидбэка — ремонтный
  цикл для ЭТОГО класса не обязателен (данные для решения о v2);
- extraction-гейт `ast.parse` критичен: без него кривой ответ портит
  workspace (теряем и задачу, и воспроизводимость);
- команда из бэктиков инструкции должна существовать в workspace —
  иначе сломанная задача (нет тестового файла) доходит до LLM зря.

## v2 — прегон тестов + ремонтный цикл (`v2/solver.py`)

Отличие от v1: suite исполняется **до** вызова LLM (бесплатно), и модель
видит готовый отчёт прогона — какие тесты падают и с какими assertion.

```
precheck (0 ток.) → ПРЕГОН suite (0 ток.)
  ├─ exit 0 ──→ DONE сразу, 0 LLM-токенов (fast-path)
  └─ падения ─→ отчёт в промпт
→ вызов: инструкция + все .py + отчёт → полный модуль → ast.parse
→ запись mylib.py → ВЕСЬ suite
  ├─ exit 0 ──→ DONE (обе позиции)
  └─ падение ─→ детектор осцилляции → ремонт (≤2 раунда): текущие
                фейлы + «BROKE эти проходившие тесты» + stderr в контекст
```

| Версия | Прегон тестов | Фидбэк/ремонт | Точность (live) | Стоимость (20 прогонов) |
|---|---|---|---|---|
| v1 «в лоб» | нет | нет | 20/20 файлов, но **1 провал** на живом (558 экв. впустую) | 470–697 экв. (медиана ~575) |
| **v2** | **да** | **да (≤2)** | **20/20, все round0** | **422–582 экв. (медиана ~476)** |

Медиана по 20 живым прогонам каждой задачи: **coding_0003 476.8 vs 573.4**
(−17%), **coding_0007 271.8 vs 305.1** (−11%). Главный выигрыш — не
медиана, а **устранение длинного хвоста**: 631–697 экв. у v1 (модель
гадает по ассертам и рассуждает вслух) против 502–582 у v2. Плюс v2
даёт **fast-path** (уже зелёная задача — 0 токенов) и не сжигает бюджет
при осцилляции.

Ремонтный цикл (кап `MAX_REPAIRS = 2`, всего ≤ 3 вызовов):
- **полная верификация** после каждого фикса: фикс, сломавший проходивший
  тест, не принимается никогда (фикс применяется к workspace, но answer.txt
  не пишется);
- **регрессионная подпись** в ремонте: «Your change BROKE these tests that
  were passing before: test_g» — так модель узнаёт о зависимости функций
  из фидбэка (ловушка взаимозависимых функций: `g` компенсирует баг `f`,
  фикс только `f` ломает `test_g`);
- **детектор осцилляции**: множество упавших тестов совпало с любым из
  виденных раньше (`A→B→A` или «фикс вернул тот же модуль») — стоп
  **сразу**, не сжигая оставшиеся раунды; статус `failed` (повтор
  множества = наша неконвергенция, а не приговор задаче → не
  `unanswerable`);
- кап раундов исчерпан без прогресса → `failed`, `answer.txt` нет.

Сознательно НЕ сделано: «подавать только упавшие функции». Экономия
input микроскопическая (входные файлы ~35 экв. из ~300–600, а 10 input =
1 output), зато частичный контекст **усиливает** ловушку
взаимозависимостей: чиня `f` без кода `g`, модель не предскажет эффект.
Дифф-патчи (режут output до ~60 экв.) — кандидат в v3, если в eval
появятся большие модули.

### Общий слой `coding/tools.py`

v1 и v2 делят детерминированную механику (0 токенов): `inspect_task`
(precheck-гейты), `target_file` / `test_command`, `files_text`,
`extract_module` (ast-гейт), `run_tests`, `parse_failures` /
`ran_count` / `test_report` (разбор stderr юниттеста), `tail_text`.
Политику (число раундов, осцилляция, что писать в ответ) решает солвер
своей версии.

**Грабли: stale `.pyc`.** Python инвалидирует bytecode-кеш по паре
**(mtime в секундах, размер файла)**. Модуль той же длины, перезаписанный
в ту же секунду (а `x / 2` → `x * 2` — та же длина, раунды внутри одной
секунды), исполняется из старого кеша: на тестах это выглядело как
«фикс не подействовал» и ложно срабатывал детектор осцилляции. Лечится
в `run_tests`: перед прогоном чистим `__pycache__`/`*.pyc` в workspace
и добавляем `-B`.

### Фиксы по итогам пакета (все в v2)

1. **Динамический кап ответа** — `reply_cap(target) =
   max(MAX_TOKENS, 1.3·токены_модуля + 300)`, оценка размера той же
   OLS символы→токены, что в `search/v2/tokens`. Статический кап 800
   гарантированно рвал большие модули: усечённый ответ не парсится,
   три раунда сгорали за 0 баллов (0035/0036/0037). После фикса
   0037 решён round0 за 3460 экв. (5 баллов).
2. **Детектор усечения** — `completion ≥ кап` + модуль невалиден →
   фидбэк «your reply was CUT OFF …» (причина, а не «not a valid
   module»), кап следующему раунду ×1.5. Повышение **одноразовое**:
   повторное усечение при 1.5× от размера модуля — болтовня, её лечит
   «compactly», а не новый кап (и граница не разлетается до 2.25C).
3. **Маркер UNSOLVABLE** — тот же контракт, что в math/v2 и DA/v2:
   противоречивые тесты → модель отвечает одной строкой `UNSOLVABLE`,
   солвер принимает отказ в любом раунде. 0046: failed 128 экв. →
   unanswerable 42 экв.

Урок 0041: контракт «полный модуль в ответе» жив даже при баге в
другом файле — модель **инлайнит зависимость** (`return round(amount *
(1 + 0.20), 2)` вместо вызова `tax_rate()`). Дырка контракта не
пробита, но решение флимки (~50%): без инлайна модель бессильна,
мультифайловые ответы — материал v3.

## cost_worst (`v2/complexity.py`)

```
solve() = precheck (0 ток.)
        ├─ ошибка precheck → EPSILON_COST (LLM не зовётся)
        └─ цикл ≤ 3 вызовов: промпт → completion ≤ reply_cap(target)
           ремонт: + эхо (≤ REPLY_CHARS) + фидбэк (фейлы + stderr)

C  = reply_cap(target); C+ = int(1.5C)+1
I0 = OLS(system + инструкция + все .py + отчёт прегона)
     отчёт прегона НЕ исполняем (медленный сабпроцесс, вклад ничтожен):
     оценка сверху 150 + 130·число_тестов символов (тест-лочится)
I_{k+1} = I_k + OLS(REPLY_CHARS) + OLS(FEEDBACK_CHARS)

cost_worst = (I0/10 + C) + (I1/10 + C+) + (I2/10 + C+)
```

Честная цена динамического капа: худший путь предполагает усечение в
раунде 0, потому оба ремонта идут с капом C+. Для малых модулей
(C=800, C+=1201) граница ≈ 4000 экв., для больших (~3400/5200) —
~15 000 экв.: триаж в worst-case режиме честно увидит дороготу.

Валидация: 55 задача-прогонов (baseline + оба adversarial-прогона),
**0 нарушений**, медианное использование границы ~3%. Задачи,
отсекаемые precheck'ом, получают EPSILON_COST=1.0, а не 0.0:
плотность reward/cost_worst делить на ноль раннер не умеет (та же
конвенция внесена и в DA/complexity).

## Что оставлено на v3 (обсуждается)

- дифф-патчи вместо полного модуля: режут output (~250 → ~60 экв.);
- «failure-neighborhood» контекст (упавшие функции + их вызывающие по
  ast-графу) — только если в eval появятся большие модули;
- защита от «модель переписала тесты» (сейчас guarded нашей записью:
  пишем только target-файл).
