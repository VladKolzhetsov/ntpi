# Предварительная оценка сложности search

`v1/complexity.py` — отдельная бесплатная эвристика, пока не подключённая к
сортировке раннера. Нужна для сопоставления будущих задач с фактическими логами.

```bash
.venv/bin/python -m solutions.search.v1.complexity --tasks-dir tasks/task-dir/task-dir
.venv/bin/python -m solutions.search.v1.complexity --only search_0032
```

Вывод — JSONL: `task_id`, `task_dir`, `predicted_steps`, `predicted_cost`,
`cost_low/high`, `confidence`, `fields`, `strategy`, `extrapolated`, `reasons`.
`--only` фильтрует по task_id из JSON, не по имени каталога.

API: `estimate(question, schema, kb=kb)` или `estimate_task(task)`.
KB опциональна: её имена помогают исключить ложные упоминания полей внутри
имён и отметить неоднозначный linking. Expected, ответы и награды не читаются.

Считаем операции DSL: `find + get + get` = 3. Повторное поле (`Father` дважды)
даёт две операции. Обратный поиск `match` = 1; `match + count` = 2.
Список выдаёт исполнитель бесплатно: отдельного шага вывода или LLM-стоимости
за каждое имя в ответе нет. Поля в `fields` идут по тексту, не по порядку обхода.

Стоимость первого вызова: `77 + 21.5 × steps`, output-эквиваленты. Исходная
калибровка — noreason/search-v1, планы длиной 1–4 из экспериментов 2026-11-11.
Другие схемы, модели и длины могут менять стоимость. Диапазон ±15% при сильных
структурных признаках, иначе ±40% — эвристика, не статистическая гарантия.
Ремонты и QA в него не входят; использовать cost_high как полный envelope рано.

Неизвестные формулировки дают низкую confidence. Синонимы ограничены словарём,
координация, скрытая глубина («Father 50 times») и длинные планы помечаются.
Прогноз не доказывает решаемость и не заменяет семантический планировщик.
Нынешний planner по умолчанию ограничен 250 output-токенами: эксперимент с
длинными цепочками должен отдельно учитывать усечение плана этим капом.

Дальше: новые перефразировки и глубины, сравнение predicted_steps с plan.steps,
первого вызова с predicted_cost, отдельный учёт ремонтов и fallback. Затем
оценка ранжирования по reward/cost при ограниченном бюджете.
