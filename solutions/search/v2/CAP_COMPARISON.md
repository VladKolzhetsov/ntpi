# Dynamic vs static cap — 2026-11-11

## Условия

Одинаковые search/v2, qwen3.8-27b-noreason, 27 задач, 3 повтора, budget=6000,
один worker, sandbox. Изменяется только выбор стартового cap через
`SEARCH_V2_CAP_MODE=static|dynamic` (default dynamic). Бюджетный гейт и
ремонт при усечении включены в обоих режимах.

Источники:
- static: `experiments/runs/20261111-133246-search-v2-static-cap`
- dynamic: `experiments/runs/20261111-133616-search-v2-dynamic-cap`

Серии выполнены последовательно: сначала все static, затем dynamic.
Побайтовые хеши файлов sandbox (кроме answer.txt) и сообщения первых
вызовов совпали. Режим виден в trace (`source=static/complexity`).

Средний расход dynamic ниже на 17.33 экв./прогон (0.56%), медианный — на
10 экв. (0.32%). Выборка мала, порядок не чередовался, ответы прокси
нестабильны: доказанной экономии или ускорения нет.

Статический requested=400 бюджетный гейт сокращал до 349–361 (envelope=420).
Dynamic: 69 первых вызовов с cap=128, 3 с 160, 3 с 349, 3 с 361.
На длинной search_0034 фактический cap=349 одинаков в обоих режимах:
это НЕ независимая проверка преимущества адаптивного лимита на длинных планах.

0034: оба режима 3/3, 309.5 экв., по одному вызову. 0033: оба 0/3,
семантически неправильный план и QA-ответ Wood вместо Chomptrick.
0029 (нет expected): static записал ответ 3/3, dynamic 2/3, в одном повторе
отказался. Это не засчитывается как verified; для противоречивой задачи
важна отдельная оценка корректности отказа.

## Вывод

На текущем наборе dynamic сокращает запас генерации, но не даёт убедительного
выигрыша в расходе или награде относительно достаточно большого static cap.
Платим за фактический output, не за разрешённый максимум. Ранжирование задач
и per-task envelope здесь не менялись; ценность модели стоимости для триажа
этот эксперимент не измеряет. Это также не сравнение с v1 и его старым cap=250.

Воспроизведение из корня:
```bash
SEARCH_V2_CAP_MODE=static .venv/bin/python experiments/run_experiment.py --label search-v2-static-cap --types search --versions search=v2 --model qwen3.8-27b-noreason --budget 6000 --repeat 3
SEARCH_V2_CAP_MODE=dynamic .venv/bin/python experiments/run_experiment.py --label search-v2-dynamic-cap --types search --versions search=v2 --model qwen3.8-27b-noreason --budget 6000 --repeat 3
```
